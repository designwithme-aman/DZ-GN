How I think

Three ideas behind every screen I ship.

Minimalism isn't an aesthetic preference — it's a discipline. Every element on screen has to earn its place, or it gets cut.

01

Clarity over decoration

If a user has to pause to interpret it, it's not designed yet. Structure, hierarchy and whitespace do the work before color ever gets involved.

02

Systems, not screens

A single beautiful screen is a coincidence. A type scale, a spacing grid and a component library are what make the next fifty screens consistent by default.

03

Code-aware design

I know what a component costs in React or Flutter before I design it, so handoff is never a translation problem — it's a copy-paste problem.

EdTech Information Architecture Client Project

SIIS — an institutional communication platform

GOAL

Rebuild a 26-screen institutional app from scratch, on a fixed six-week client timeline.

APPROACH

Rebuilt structure from the Figma source of truth and prioritised the Communication module as the highest-value flow first.

SOLUTION

A four-tab architecture — Home, Dashboard, Communication, Profile — modeled on messaging patterns staff already knew.

STACK

Enterprise Dashboard RBAC

College ERP — one system, three roles

GOAL

Replace three disconnected tools with one system that students, faculty and admins could all use.

APPROACH

Mapped permissions and data flows before any screen existed, so UI could follow one role-based logic layer.

SOLUTION

The process

Same four steps, every project.

01

Discovery

Understand the users, the constraints and what "done" actually means before opening Figma.

02

Prototyping

Wireframes, then a real design system, then high-fidelity screens the team can react to fast.

03

Development

Build the components myself where useful, so nothing gets lost in a design-to-code handoff.

04

Handoff

Documented components, redlines and a system that survives past the first release.
